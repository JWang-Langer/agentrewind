**录制命令**：`./.venv/Scripts/python.exe examples/run_demo.py --video --pause 2`
**原则**：画面全部来自真实终端运行，不做剪辑伪造；**不要遮挡随机结论编号**——它是可信度的来源。

> ⚠️ 关于数字：结论编号（如 `[652230507]`）与 run_id 每次运行都会变。**不要背剧本里的具体数字**，
> 录制时照读屏幕上的实际值。本稿中的数字来自一次真实运行，存档在
> `docs/competition/artifacts/demo_run_video.log`，可用于核对。

## 镜 1（0:25–0:55）问题陈述

**画面**：终端里 README 的第一屏（`cat README.md` 或编辑器滚动），停在"它解决什么问题"那张表。

**旁白**：
> 智能体上线以后，你每天面对三件事。
> 第一，不可复现——线上失败的那一次，本地重跑十次都正常；因为大模型采样本身不确定，
> 而且重跑还会重复扣费、重复写库。
> 第二，不可归因——改了一行提示词，行为整体漂移，但你**说不清是从第几步开始漂的**。
> 第三，"某一次运行的表现"没法变成回归测试：现有工具只能**看**，不能**重跑**。
> 这三件事的根源是同一个：大模型采样和外部副作用这两条边界，没有被当成一等公民来建模。

**录制提示**：这段可以边滚动边说，不要放静态图。

## 镜 2（0:55–1:40）录制：让 Agent 真跑一次

**操作**：
```bash
./.venv/Scripts/python.exe examples/run_demo.py --video --pause 2
```

**屏幕要点（照读实际值）**：
```
stub 上游已启动: http://127.0.0.1:xxxxx/v1
▶ 0) 起点：让 Agent 跑一次真实上游，边跑边录
  $ arw record --agent examples.demo_agent:main --name demo-run --base-url $STUB
>>> 录制 run_id = 01M4ZV9WAJ20K4DMP91WGXW7G5
>>> 上游被真实调用了 2 次；结果 = 'SKU-1 价格 199.00 元。结论编号[652230507]'
```

**旁白**：
> 先让它真跑一次。这是一个最小的比价智能体：先问模型要不要查价格，
> 模型返回一次工具调用，智能体去打外部价格接口，再问模型把结果写成结论。
> 整个过程两次模型调用、一次外部接口请求，全部被录下来。
>
> 注意屏幕上这句结论后面的编号——它是上游每次随机生成的。
> 接下来，这个随机编号就是判定"确定性"的指纹。如果回放偷偷重新采样，这个数一定会变。

**录制提示**：
- 终端窗口别太窄（≥100 列），否则 `>>>` 行会折行；
- 鼠标在结论编号那一行停留 2 秒，让观众看清；
- `--pause 2` 会在关键结论后停 2 秒，正好用于这句旁白。

## 镜 3（1:40–2:30）回放：核心证据

**操作**（脚本自动执行）：
```bash
arw replay <上一步的 run_id> --agent examples.demo_agent:main
```

**屏幕要点**：
```
>>> LLM 命中 2 次 / 上游新增调用 0 次
>>> 回放结果 = 'SKU-1 价格 199.00 元。结论编号[652230507]'
>>> 结论编号与录制时完全相同 —— 这就是'确定性回放'
```

**旁白**：
> 现在，不改一行代码，直接回放。
>
> 两次模型调用全部命中录制，**上游新增调用是零**——它根本没有碰网络。
> 而结论编号，与刚才那一次完全一致。
>
> 这就是可观测的确定性：我们没有去断言"某个函数被调用过"，
> 而是用一个随机编号证明——回放拿到的是**录制时的同一份响应**，逐字节一致。
> 副作用的处理方式完全一样：那个外部价格接口，在回放时不会被真的请求。

**录制提示**：这是全片最重要的一镜。**把"0 次"和编号一致的画面留足 4 秒**，
旁白说完后再停 1 秒再切。

## 镜 4（2:30–3:10）当 CI 门禁用

**操作**（脚本自动执行两条）：
```bash
arw verify <run_id> --agent examples.demo_agent:main          # 退出码 0
arw verify <run_id> --agent examples.demo_agent:main --set system_prompt=你现在只说'不告诉你'   # 退出码 3
```

**屏幕要点**：
```
>>> verify 退出码 = 0（0 = 可与录制完全一致地重跑）
[stderr] [replay] 检测到分歧（这是分叉点）：第 1 步（第 1 次 LLM 调用）与录制不一致，共 1 处差异
>>> 改了 system prompt 后 verify 退出码 = 3（3 = 检测到分歧）
```

**旁白**：
> 于是它可以直接当 CI 门禁用，靠退出码说话。
>
> 同样的代码，回放一致，返回 0。现在我改一句系统提示词——它立刻报出分歧，
> 并指出这是**第 1 步**就出现的不一致，返回退出码 3。
>
> 这意味着，"某一次线上运行的表现"可以被固化成一条回归测试：
> 跑一遍几秒钟、零调用成本、结果可复现。

**录制提示**：说"第 1 步"时，用鼠标划一下 stderr 那行（终端里的红/黄字）。

## 镜 5（3:10–3:55）回退到某一步改一改

**操作**（脚本自动执行）：
```bash
arw rewind <run_id> --at 3 --set second_note=  【回退分支：补充了差价说明】 --base-url $STUB
```

**屏幕要点**：
```
>>> 新分支 run_id = 01M4ZV9ZJ728XGEV4BB03N4T9A
>>> 命中 1 步后分叉，真实重跑 1 次
```

**旁白**：
> 更常用的是这一句：**如果当初在第 3 步换一种做法，会怎样？**
>
> 我从第 3 步回退，改掉喂给模型的工具结果，然后**从这一步起真实重跑**。
> 前面命中录制，后面真实调用上游——本次只新增了 1 次调用。
>
> 关键在"分叉点"这个词：它不是我们指定或猜测的，
> 而是回放时**逐步比对请求指纹**比出来的第一个不一致位置。

**录制提示**：这句"不是我们指定或猜测的"要重读，是技术卖点。
另外注意措辞：`--at 3` 在 CLI 里只是**标注"期望的分叉步号"，不参与控制流**
（`arw rewind --help` 原文：*提示用：期望的分叉步号（仅用于打印，不影响控制流）*）。
真正的分叉位置由回放时的指纹比对决定。旁白里**不要说"我指定从第 3 步分叉"**，
要说"我预期它会在第 3 步分叉，而工具确实在第 3 步发现了不一致"。

## 镜 6（3:55–4:35）差在哪一步、为什么差

**操作**（脚本自动执行）：
```bash
arw diff <原 run_id> <新分支 run_id>
arw why  <原 run_id> <新分支 run_id> --index 1
```

**屏幕要点**：
```
差异报告: 01M4ZV9W…  vs  01M4ZV9Z…
  步数 4 vs 4｜分叉点 seq=3｜不同步数 1
  token 305 vs 305（Δ+0）｜耗时 48ms vs 69ms
    seq 3   diverged   llm  工具 [] -> []
        -SKU-1 价格 199.00 元。结论编号[652230507]
        +SKU-1 价格 199.00 元。结论编号[459222270]

第 1 次 LLM 调用：a486eaf3c2c4 vs 51dffd246589
  差异 1 处
    changed  messages[3].content: '{…"sku":"SKU-1"}' -> '{…"sku":"SKU-1"}  【回退分支…】'
```

**旁白**：
> 两条分支差在哪一步、代价差多少，一条命令给出来。
> 分叉在第 3 步，token 完全一样，只有下游结论不同。
>
> 再问一句"**为什么**差"，它精确指到 `messages[3].content` 这一个字段。
> 这跟"翻了半天调用链，说好像是这里不一样"是两回事——
> 它是请求级、可枚举的差异列表。

**录制提示**：说"messages[3].content"时鼠标划过该行（脚本已用高亮色标出差异值）。

## 镜 7（4:35–5:00）全景与收尾

**操作**（脚本自动执行）：
```bash
arw list
arw show <新分支 run_id>
```

**屏幕要点**：
```
id                          name                        mode    status    steps
01M4ZV9ZJ7…  replay:demo-run             rewind  replayed  4
01M4ZV9WAJ…  demo-run                    record  finished  4
01M4ZV9ZJ7…（replay:demo-run） 谱系 01M4ZV9WAJ… <- 01M4ZV9ZJ7…
  seq 0   note    fp=-             ''
  seq 1   llm     fp=43555612fe5d  tools=['lookup_price']
  seq 2   effect  fp=-             ['price_api', 'SKU-1']
  seq 3   llm     fp=51dffd246589  tools=[] text='…[459222270]'
```

**旁白**：
> 所有运行、分支谱系，都落在一个本地 SQLite 文件里：可以入库、可以进 CI、
> 可以把线上失败的那一次完整带回家复现。
>
> 一句话总结：**观测工具回答"发生了什么"，AgentRewind 回答"再跑一次会不会一样、
> 不一样是从哪一步开始的"。** 前者是账本，后者是版本控制。
>
> 代码 Apache-2.0 开源，仓库地址在简介里。

**录制提示**：最后一句说完，画面停在 `show` 的谱系行 2 秒再淡出。

## 录制前检查清单

- [ ] `./.venv/Scripts/python.exe examples/run_demo.py` 先空跑一次，确认 stub 端口不冲突、无报错
- [ ] 终端字号 ≥16pt、窗口 ≥100 列，历史滚出区已清（`clear`），避免露出无关路径
- [ ] 关闭会弹通知的软件；浏览器标签全部关掉
- [ ] 用 `--pause 2` 起录；若配音语速慢，用 `--pause 3`
- [ ] 录完后逐镜核对：**结论编号一致的那一帧必须在成片里清晰可见**
- [ ] 成片导出后再自查一遍"是否有任何生成图/假画面"——零容忍

## 常见翻车点

| 现象 | 原因 | 处理 |
|---|---|---|
| `>>>` 行折行难看 | 终端列数太窄 | 窗口拉宽到 ≥100 列 |
| 提示端口被占用 | 上一次 stub 未退出 | 重开终端；stub 用系统随机端口，一般不冲突 |
| 数字与剧本不一致 | **正常**，编号每次随机 | 照读屏幕实际值，勿背稿 |
| diff 的 token 数变了 | 输入长度或模型行为变化 | 无妨；旁白不要说"永远是 305" |
| 画面里出现真实 API Key | 用了真实上游 | 本演示只用本地 stub，不要换成真实服务录制 |
