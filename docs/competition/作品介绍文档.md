## 一、问题：Agent 的 bug 复现不了，改一行 prompt 不知道影响了哪一步

智能体进入生产后，工程团队每天面对三类具体困境：

1. **不可复现**：线上失败的那一次运行，本地重跑十次都正常。原因是 LLM 采样本身不确定，
   加上工具/接口有副作用，重跑还会重复扣费、重复写库。
2. **不可归因**：改了一行 prompt 或一个工具描述，行为整体漂移，但**说不清是从第几步开始漂的**。
3. **不可回归**：想把"某次运行的表现"变成 CI 里的一条测试，却没有可用的机制——
   现有观测工具只能**看**，不能**重跑**。

这三件事的共同根源：LLM 交互边界（采样）与外部副作用边界（工具调用）
**没有被当作一等公民建模**，于是"确定性"在 Agent 里成了一句空话。

---

## 二、方案：把两条不确定边界录下来，让 Agent 重新变确定

核心洞察是**边界缩减**：Agent 的代码本身是确定的
（同一份代码 + 同一串输入 ⇒ 同一串输出），不确定的只有两类边界——
LLM 采样与外部副作用。把这两类边界的输入输出录制下来、回放时按指纹复用，
整个 Agent 即可确定性重放。

由此得到一个**可验证的强断言**（也是本项目的核心测试）：

```
同一份 Agent 代码 + 回放  ⇒  零上游调用  +  结果与录制逐位一致
```

四项关键机制：

| 机制 | 说明 |
|---|---|
| **请求指纹** | `SCHEMA_VERSION + 规范化 JSON(请求)` → SHA-256 取 128 位。规范化含键排序、紧凑分隔符、保留 `None`（`temperature=None` 与 `0.0` 语义不同，丢弃它会造成"假命中"） |
| **事件日志** | SQLite（WAL）三表 `runs/steps/effects`，每步写入即提交；payload **逐字节忠实往返**（不排序键） |
| **副作用幂等** | `session.effect(name, key, producer)`；回放命中则直接返回录制值且**不执行** producer |
| **分叉与差异** | 回放逐条比对指纹，**首个不一致即分叉点**；`diff` 给分叉步号/工具变化/文本增量/token 与耗时差；`why` 给到 `messages[i].content` 级差异路径 |

### 真实运行证据（可复现）

```
0) 录制：上游被真实调用 2 次；结果 = 'SKU-1 价格 199.00 元。结论编号[829427182]'
1) 回放：LLM 命中 2 次 / 上游新增调用 0 次；结果 = 'SKU-1 价格 199.00 元。结论编号[829427182]'
2) verify 退出码 = 0；把 system prompt 换掉后 = 3（检测到分歧，可作 CI 门禁）
3) rewind：命中 1 步后在第 3 步分叉，从该步起真实重跑 1 次
4) diff：分叉点 seq=3｜不同步数 1｜token 305 vs 305
5) why：changed messages[3].content → 精确到具体消息字段
```

复现命令：`python examples/run_demo.py`（内含带随机 nonce 的本地 stub 上游——
如果回放偷偷重新采样，nonce 必然变化，因此这是**可观测的**确定性证明）。

## 三、与同类方案的明确技术优势

| 同类方案 | 能力边界 | 本项目的差异 |
|---|---|---|
| LangSmith / Langfuse / OTel trace | 观测：把发生过的事展示出来 | 不能把运行重跑成同一结果；本项目可，且零上游调用 |
| LangGraph checkpoint / time travel | 图内状态恢复 | 恢复后 LLM 仍**重新采样**，且绑定 LangGraph；本项目框架无关、逐位一致 |
| VCR / Polly.js 类录制回放 | 拦截被 patch 的函数 | 键设计粗糙（URL+序号），无法在"改了 prompt 哪一行"的粒度定位分歧；本项目用语义完备请求指纹 |
| 语义缓存 | 按相似度命中，目标是省钱 | 相似命中会**换答案**，与"可复现"目标冲突；本项目按字节精确命中 |

一句话：观测工具回答"**发生了什么**"，AgentRewind 回答"**再跑一次会不会一样、不一样是从哪一步开始的**"。

## 四、按评审维度自查（诚实版）

### 技术创新（30%）—— 我们的主张与证据

- **主张**：把"确定性重放"从理念落成可执行断言，靠三条设计（语义完备指纹 / 忠实往返存储 / 显式副作用幂等）。
- **证据 1**：`docs/design-notes.md` 记录了 **4 个真实缺陷**及其根因与回归测试，
  其中 **缺陷 #1「存储排序键破坏回放确定性」** 是典型的"隐式非确定性"案例：
  `sort_keys=True` 让副作用值的键序在存取之间被重排，prompt 字节随之改变，回放被判为分歧。
  这类问题只会静默地让数天后的回放失败。我们把它定位、修复、固化成回归测试。
- **证据 2**：测试断言的是**行为契约**而非实现细节——回放逐位一致、零上游调用、
  副作用不重复执行、三类分歧（改 prompt / 多调用一次 / 缺副作用）必须被精确捕获。共 35 个测试全绿。
- **刻意避免"重复造轮子"**：不重做大盘、不做 mock 框架、不引入厂商 SDK；
  依赖仅 3 个（httpx / pydantic / pydantic-settings）。

### 场景落地（30%）—— 能跑、能测、场景真实

- 可运行：`pip install -e . && arw record/replay/verify/rewind/diff/why`，端到端演示一条命令复现。
- 可测试：`arw verify` 直接作为 CI 门禁（退出码 0/3），把"某次运行"固化为回归用例。
- 真实场景：Agent 线上事故复盘、prompt 与工具描述变更的回归、多智能体协作中定位"哪个 Agent 先漂移"。
- 验证数据来自**真实 HTTP 上游**（本地 stub 亦是真实 HTTP 服务，不是 mock 替换）。
- 部署条件：纯 Python 库 + CLI，无 GPU、无外部服务依赖，单文件 SQLite 即全部状态。

### 开源治理（20%）—— 已就位

- 许可证：Apache-2.0（含专利授权），`LICENSE` 完整。
- 依赖合规：`docs/dependency-audit.md` 逐条列出许可证与兼容性结论，无 GPL/AGPL 风险。
- 协作规范：`CONTRIBUTING.md`（含 DCO、提交信息规范、测试要求）、`CODE_OF_CONDUCT.md`、
  `SECURITY.md`（私下报告流程）、Issue/PR 模板、`CHANGELOG.md`（Keep a Changelog 格式）。
- 文档规范：`README.md`（快速开始 + 实测输出）、`docs/design-notes.md`（含缺陷档案）、
  `docs/prior-art.md`（同类方案对比）。
- 新项目说明：本项目为**新建仓库**，治理文件在首个提交时即随库落地（而非事后补），
  这是"治理意识"的直接体现。

### 长期发展（20%）—— 路线图与维护承诺

- 路线图（`README.md` 与 `CHANGELOG.md` 同步）：副作用自动拦截层 →
  流式响应分块录制 → 跨进程/跨语言指纹兼容夹具 → `arw bisect`（自动二分定位引入行为变化的最小改动）。
- 维护机制：单维护者 + 明确的 Issue 分类与响应预期；测试与代码规范（ruff/black/mypy strict）
  保证外部贡献可被安全合入。
- 生态位清晰：作为**库**被上层 Agent 框架/平台集成，而非与之竞争。

## 五、诚实边界（不夸大）

- v0.1 只覆盖**非流式** `/chat/completions`；流式在路线图内。
- 副作用需 Agent 作者**显式声明**（刻意设计，见 design-notes 决策 4）；自动拦截层尚未实现。
- 指纹是请求级的：若上游改变了对同一请求的返回（模型升级），回放仍返回录制值——
  这既是可复现性的来源，也可能掩盖上游漂移（可用 `--on-divergence live` 观察）。
- 尚未在超大规模（>10 万步）库上做性能验证；当前定位是单机开发与 CI 场景。
- 本项目当前只有 1 名维护者，长期发展依赖社区参与（这也是我们希望借赛事获得的资源）。
