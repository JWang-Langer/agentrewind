# 第三方依赖与许可证审查

开源治理维度要求"协议和第三方依赖是否合规"。本项目刻意把依赖压到最小，
并在下表中逐条说明用途与许可证。**运行时依赖只有 3 个。**

## 运行时依赖

| 包 | 版本约束 | 用途 | 许可证 | 合规判断 |
|---|---|---|---|---|
| `httpx` | >=0.27 | 异步 HTTP 客户端（调用 OpenAI 兼容上游） | BSD-3-Clause | 允许商用、允许闭源分发，与本项目 Apache-2.0 兼容 |
| `pydantic` | >=2.7 | 数据模型与校验 | MIT | 兼容 |
| `pydantic-settings` | >=2.3 | 环境变量/配置读取 | MIT | 兼容（当前仅少量使用，保留供 CLI 扩展） |

## 开发期依赖（不随包分发）

| 包 | 用途 | 许可证 |
|---|---|---|
| `pytest` | 测试运行器（可选；标准库 `unittest` 亦可运行全部测试） | MIT |
| `ruff` / `black` | 代码检查与格式化 | MIT |
| `mypy` | 静态类型检查（`strict` 模式） | MIT |

## 刻意**不引入**的依赖

| 未引入 | 原因 |
|---|---|
| 各厂商 LLM SDK（`openai` / `anthropic` …） | 绑定厂商且版本漂移快；只用 HTTP + 标准响应结构即可，保持"框架无关" |
| 任何测试 mock 框架 | 测试用**真实 HTTP stub 服务**（`agentrewind.testing.stub_server`），避免 mock 与真实行为的偏差 |
| Web 框架 / 前端框架 | 本项目定位是本地优先的库 + CLI，不做服务端与大盘 |
| ORM | 直接用 `sqlite3`，避免为单表日志引入迁移框架 |

## 许可证兼容性结论

- 本项目采用 **Apache-2.0**（含专利授权条款，适合被企业与下游项目采用）。
- 全部运行时依赖均为 **BSD-3-Clause / MIT**（宽松许可），无 GPL/AGPL 传染风险。
- 示例与测试代码中不包含任何第三方来源的非自由代码。
- 贡献者需签署 DCO（见 `CONTRIBUTING.md`），保证贡献的来源可追溯。

> 说明：本表由项目维护者依据各依赖仓库自身的 LICENSE 声明人工核对。
> 若上游变更许可证，需在发布前重新审查（已列入 `CHANGELOG.md` 的发布检查项）。
